# Tag releases

Push an existing `vMAJOR.MINOR.PATCH` tag (optionally `-rc.1` or another SemVer
prerelease suffix), or dispatch Release with that tag. Tags must resolve to a
commit reachable from `origin/master`; lightweight and annotated tags work.
Build metadata (`+...`) is intentionally excluded from the package version syntax.
No workflow creates, moves or deletes tags. Branch and pull-request CI verifies
formatting, three-OS vet/tests, five CGO-disabled command builds and script checks.
Release invokes that same CI before packaging.

Release notes use `docs/releases/v<VERSION>.md`; without that file, they use the
commit log after the nearest preceding reachable `v*` tag (all history for a
first tag). Signing status is appended from package provenance. Placeholder notes
must be completed by the reviewer before tagging.

Packages are built on macOS with `VERSION` in the environment. `release.sh`
verifies package structure, payload architecture, provenance and SHA256SUMS.
Windows and macOS packages are unsigned when their credentials are unavailable.
A version suffix or either unsigned platform makes the release a prerelease.
Linux has no platform code-signing hook. Compilation and CI tests do not certify
installation, runtime rendering, Apple notarization acceptance or Windows trust.
See [implementation status](../IMPLEMENTATION_STATUS.md) for the feature matrix.

## Optional GitHub Actions secrets

- Windows: `WPAPP_WINDOWS_PFX_BASE64` and optional
  `WPAPP_WINDOWS_PFX_PASSWORD` provision a PFX for osslsigncode. `WPAPP_SIGN_CMD`
  overrides the default command and can also provision its own credentials;
  the existing hook substitutes `{}` with the file path. The PFX and password
  file paths are available as `WPAPP_WINDOWS_PFX` and
  `WPAPP_WINDOWS_PASSWORD_FILE`. The command must fail if signing fails.
- macOS: `WPAPP_MACOS_P12_BASE64`, `WPAPP_MACOS_P12_PASSWORD`, and
  `WPAPP_CODESIGN_ID` provision an ephemeral keychain. Optional
  `WPAPP_APPLE_ID`, `WPAPP_APPLE_PASSWORD`, `WPAPP_APPLE_TEAM_ID` enable notarization;
  `WPAPP_NOTARY_PROFILE` selects the temporary profile name. Missing required
  credentials skip that platform's signing or notarization. Invalid supplied
  credentials fail the build rather than claiming success.
- Updater: `WPAPP_UPDATE_KEY` and `WPAPP_UPDATE_PUB` contain the base64 text
  generated by `wpupdate keygen`. With both present, the public key is embedded
  and the private key signs manifests, which are verified before archiving.
  Missing either skips updater signing. The additional `updates.tar.gz` contains
  bare command payloads for the existing updater protocol; it is not a signed
  macOS app replacement or a production update-feed deployment. Platform signed
  installers remain the supported manual distribution. Keys are never uploaded.

## Retry and local verification

Publication first creates a draft, checks all remote hashes, uploads only missing
assets, then publishes. Existing assets and metadata are never overwritten.
The exact package artifact is retained for 90 days and reused by later attempts
and dispatches for the same tag/commit, avoiding timestamp/signature differences
from rebuilding. After artifact expiry, complete drafts and published releases reuse their own
verified assets. Partial drafts require their original verified artifact before
resuming; they are never rebuilt over existing assets. Changed bytes, changed
tags, conflicting metadata and interrupted server-side `starter` assets require
operator review, never automatic replacement.

Local checks: `python3 -m unittest discover -s scripts -p 'test_*.py'`,
`bash scripts/release-self-test.sh`, `bash scripts/check.sh` and
`VERSION=0.3.1 bash scripts/release.sh`. Packaging requires Go from go.mod, Python,
NSIS, 7z/7zz and sha256sum (on macOS add Homebrew coreutils' `libexec/gnubin` to
PATH). Apple signing additionally requires macOS. Local dirty builds may be
inspected but cannot be published. This checkout's release work changes no Go
source; hosted runners and real signing credentials still require live validation.
