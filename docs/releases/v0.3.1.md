# Wallpaper v0.3.1

## Changes

- New native interface in a Wallpaper Engine–style layout. The wallpaper library sits in the centre, with a property panel beside it, compact top and bottom bars, and no icons. The displays page and every settings page use the same design.
- Each wallpaper keeps its own playback settings: volume, mute, fill mode and speed. Any display can override them or follow the wallpaper.
- Imports can be cancelled; items that finished importing stay in the library. Picker failures and cancellations are reported.
- Video wallpapers can be optimised per display (F-07). A cover-cropped version is encoded at each screen's native size, one job at a time. The player switches to it in place without restarting.
- Web wallpapers (F-12) run on WebView2 (Windows) or WKWebView (macOS) in an isolated helper process. The helper starts only while a web wallpaper is shown.
  - Packages are served from a private origin.
  - Network access, navigation, pop-ups, downloads and permission requests are denied unless you allow network access for that wallpaper.
  - Properties are passed in one way only, and the frame rate is capped.
- Shader wallpapers (F-14) render on the GPU with D3D11 (Windows) or Metal (macOS). GLSL is translated natively, and render scale adapts to stay within the frame budget. No WebView is involved.
- Audio-reactive (F-22) and mouse-interactive (F-26) wallpapers.
  - Inputs:
    - System audio is captured as a 128-bin spectrum in the isolated helper, through WASAPI loopback or ScreenCaptureKit.
    - The cursor position is mapped across mixed-DPI displays.
  - Shaders receive these as `iAudio` and `iMouse`; web wallpapers can receive them too.
  - Safeguards:
    - Both features are off by default.
    - A wallpaper gets them only if it declares them and you grant them; you can revoke them per wallpaper.
    - They stop while a fullscreen app is running, and while the wallpaper is covered, the screen is locked or the system sleeps.
- CI/CD:
  - Pull requests and branches run format, vet and test checks on Linux, macOS and Windows, plus five cross builds.
  - Pushing a `v*` tag runs the same checks, builds the packages and publishes the GitHub release.

## Fixes

- Repeated clicks no longer duplicate updates or destructive actions. Cancelling a confirmation dialog does nothing.
- Deleting a wallpaper waits for its encoder to release file handles (Windows).
- Rule matching uses the target OS's case rules; quoted paths work with mpv.
- Windows render helpers are per-monitor DPI aware.

## Known limitations

- Linux: web and shader wallpapers are not supported.
- macOS audio capture needs Screen Recording permission. Without it, you get a clear error; the app does not request the permission automatically.
- Not provided: a store or Workshop listing (F-21), online services (F-25), or a replacement for the non-public Aerial screensaver assets (F-23).
- No hosted update feed is configured.
- Without signing credentials, packages are unsigned and this is a prerelease.

## Validation

- The Linux, macOS and Windows hosted CI checks above all pass.
- All 19 GLSL→MSL golden shaders compile on a real Metal GPU. On the same machine, the GPU preview path rendered the sample shader correctly.
- Not yet validated on real hardware:
  - Windows: D3D11 rendering, WebView2 and WASAPI capture.
  - macOS: ScreenCaptureKit capture.
  - Performance on long multi-display runs.
