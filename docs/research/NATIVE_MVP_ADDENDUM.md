# 原生 MVP 研究接续（2026-10-21 UTC）

这份补充将原设计与本轮主分支源码对应，不修改三份早期调研的原始结论或日期。实现基线为 `master/2710033ef169852bd7c4a1b5c063d29f3f3e89fd`；`ui/5f00d334cd32412291964d228fad4f3b9461cc7b` 仅为设计参考，React 不进入产品。本轮 AVFoundation/MF/purego 的 API 与 ABI 选型由实现和代码复核对照主要文档/源码，新技术依据与旧市场/法律资料的时效复核分别看待。以下接续以【当前源码】为主，实际命令/结果只以 [验证记录](../VALIDATION.md) 为准；没有 Windows/macOS 真机、签名、服务上线或新增市场/法律调查证据。

## 1. 多屏：空间跨屏与同步播放是两个问题

[原生跨屏实现](../SPANNING.md) 对每块物理屏保留独立宿主、渲染器、可见性状态机和队列。视频渲染到共同虚拟画布，宿主裁切各自区域；静态图和视频首帧通过有界图片裁切生成各屏 PNG。负坐标、错位、空隙和拓扑改变进入几何计算，不是把完整画面各播放一次。

选择这条路线能沿用按屏暂停及故障恢复，但代价是每屏仍独立解码，暂停后各屏视频时间可能不同。单解码器共享纹理/跨 GPU 输出、共同帧时钟与无缝同步并未实现，不能用“跨屏已接线”推出这些能力。Windows/macOS 混合 DPI、同数量拓扑变化、宿主重建、GPU 纹理限制及实际接缝仍需真机证据。Linux 单输出宿主不提供本能力。

## 2. 转码：平台原生路线优先，能力按实际产物确认

[转换契约](../../internal/transcode/README.md) 和 [`encoder.go`](../../internal/transcode/encoder.go) 明确选择顺序：显式配置的 ffmpeg → 可用的 macOS 应用原生 helper → PATH 中的 ffmpeg → macOS 有限 avconvert 回退。显式坏路径、已选编码器失败或不支持输入不会悄悄换路线；不下载、不捆绑编码器。

- macOS 默认通过自身 `-helper transcode` 子进程调用系统 AVFoundation，使用 AVAssetImageGenerator 和 AVAssetWriter/像素缓冲适配器生成 H.264。GIF 在 helper 中用 Go 解码和合成，保留子矩形、透明、帧延迟和 disposal，再编码一次完整循环。无须先安装 ffmpeg。非正方形 GIF 像素比例和 plain-text 绘制明确不支持，不能静默拉伸或遗漏后当作正确转换。
- 可选 ffmpeg 的 macOS 路线要求 `h264_videotoolbox`，Windows 要求 `h264_mf`；不替换成 libx264。Linux 保留外部 libx264 软件兼容路线。选中系统编码器不等于证明硬件加速，VideoToolbox 路线允许系统自身的软件实现。
- 严格路线要求 H.264 MP4、恒定 30fps、无音轨、首同步样本和有界 GOP、偶数尺寸。先写私有临时文件，检查 MP4 样本表、时长/帧数与尺寸，再原子发布；取消和失败不破坏旧产物。样本表验证不是完整 bitstream 解码，云端 ffprobe/解码/IDR 检查只证明所测 Linux ffmpeg 产物。
- avconvert 仅为明确标注的有限回退；不支持 GIF，也不承诺固定 30fps、目标尺寸或去音轨，不能据此关闭原 F-07。

### 当前实现与原 F-07 的剩余差异

[`encodingTarget`](../../cmd/wallpaperd/encoder.go) 支持主屏当前模式 backing 像素尺寸或 1080p/1440p/2160p；任务启动时重新取显示器拓扑。macOS 逻辑坐标与 backing 像素分列，静态裁切也按后者输出；Windows 已是物理像素的边界不重复乘 DPI，缩放 Retina 模式的 backing 栅格也不等于固定面板最大尺寸。缩放保比例、不放大、偶数对齐，以尺寸边界为上限。当前每素材一份共享产物，不是原设计“每块屏按 cover 裁切、分辨率缓存多份”的完整 rendition 管理；后者仍缺独立实现，而不只是缺一次真机测试。

原生 helper 采用逐帧图像提取，优先保证边界与输出契约，不是 AVAssetReader 的零拷贝吞吐优化。输入/帧数/像素/时长有上限，取消依靠父进程终止独立 helper；这是进程隔离，不是安全沙箱。mac 真机需补 24/25/29.97/60fps、方向/旋转/像素比例、复杂透明 GIF、末帧、编码器繁忙、内存压力与取消测试。未支持的原生解码格式须报错，可由用户显式选择兼容 ffmpeg，不能承诺原生覆盖全部视频容器。

## 3. 指标：暂停时间不是能源节省

[`runtimeMetrics`](../../internal/app/metrics.go) 统计已确认的动态壁纸状态，L0–L4 分列，L1–L4 合为“本周暂停时长”。数据写入 state.json schema 2，当前周按 UTC 周一切换；每个指标显示器键为 SHA-256 前 16 字节的十六进制摘要，最多 64 个，有限计数不保存素材路径、窗口标题或进程名。

统计不追补离线时间；不计静态图、未启动/失败和系统睡眠；超过 45 秒的采样间隔整段舍弃。时钟回退或异常跳变不重复计时，跨周仅保留新周部分。后端未确认的暂停/终止不能充当已节省的时间。

UI 直接展示这些状态和计数，不注入示例周时长。它们既不是瓦时/电池续航测量，也不是估算节电量。mpv 硬解标识取实际后端报告，MF/AVF 仍报告未知；框架名、GPU 请求参数和软件截图都不能代替硬解证据。原第 16 章的延迟直方图、首帧耗时等扩展指标没有因此全部实现。

## 4. 后端属性不能只保存在 UI

每屏 fit/speed 通过实际渲染器能力和 `UpdatePlayback` 接线，不支持的控制必须明确报错或回退。mpv/MF/AVF 已有原位调整路径；MF 使用原生播放速率/时间接口，按源画面比例裁切、letterbox 或交换链 stretch，串行更新属性并在异步 seek 完成后播放。MF 不支持帧降采样，最终测试情况以 [矩阵](../IMPLEMENTATION_STATUS.md) 和 [验证记录](../VALIDATION.md) 为准。只有设置值持久化不能证明后端执行，原位更改也不能推出真机 ≤200 ms AC。

对所有后端都要检查暂停时修改不自行播放、位置不跳回、L3/L4 恢复、错误回滚、重复点击及退出重建。全局后端/音频/降采样配置仍可能重建。MF/AVF 真机渲染、硬解、循环和速度准确性仍须逐平台确认。

## 5. 完成判断必须分层

| 类别 | 例子 | 关闭条件 |
|---|---|---|
| 当前源码与云端可验证逻辑 | 几何裁切、GIF 合成、队列/迁移/本周计数、配置与 UI 控制 | 对最终源码跑适用单元/race/构建及回归；模拟器不外推真机 |
| 已有原生源码，缺目标运行证据 | Win/mac 桌面宿主、原生编解码、MF/AVF 控制、混合 DPI/电源/硬解 | 对应系统硬件、素材、日志/录屏、测量及逐项 AC |
| 仍缺产品架构或功能 | 按屏多 rendition、F-12 Web 沙箱、F-14 Shader、F-25 在线服务 | 实际实现、安全/权限/内容与服务设计，然后验证；不能仅安排硬件测试 |
| 独立发行授权与资产 | 证书、签名/公证、商店账号、更新源/可信公钥 | 实际授权/配置、生成并验证发行物，不由 UI 开关替代 |

原规格 F-12/F-14 属 v1、F-25 属“以后”、F-26 在 v0 明确不支持。它们仍在 [F-01…F-26 矩阵](../IMPLEMENTATION_STATUS.md) 中，不默默删除，也不把后来范围排除假定为用户批准；本次是否覆盖全部 v1/roadmap 仍待确认。
