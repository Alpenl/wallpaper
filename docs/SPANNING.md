# 原生跨屏画布实现

本文描述当前主分支原生应用的跨屏实现，不把 UI 设计稿或交叉编译当作真机验证。

## 行为与架构

- 默认仍是独立显示器模式。切换到跨屏时，使用当前选中显示器的壁纸作为跨屏内容；独立模式下的默认壁纸、每屏分配、填充与速度设置仍保留，切回后恢复。
- 跨屏是同一虚拟桌面画布的不同空间裁切，不是把同一张完整画面复制到每个屏幕。负坐标、纵向错位、不同尺寸、布局中的空隙和重叠均按系统桌面坐标保留。
- 每块物理屏仍有独立的稳定 ID、原生窗口、渲染器、可见性状态机和串行工作队列。Windows 外层 HWND 裁切位移后的内层画布 HWND；macOS 外层窗口的裁切 layer 包含完整画布 NSView。
- 画布位置使用宿主的虚拟桌面坐标：Windows/X11 的 Bounds 是物理像素，macOS 的 Bounds 是逻辑点；不能按某块屏的 DPI 放大所有原点。macOS Cocoa 的向上 Y 轴单独转换。当前模式的 backing 像素尺寸单独存为 Pixels/PixelW/PixelH，用于转码和静态图输出，不改变跨屏空间映射；Windows 已是物理像素的尺寸不再次乘 DPI。显示器尺寸、backing 分辨率、缩放、主屏变化、插拔和桌面恢复会重建相应原生视图。
- 跨屏壁纸、填充方式和速度共享；手动暂停、自动遮挡/全屏、电源状态与性能档位依旧按屏执行。暂停一块屏可能让运动画面与其他屏不同步，这是保留按屏暂停的取舍。
- 这里没有单一解码器或跨进程帧时钟，不保证视频逐帧同步。共同的续播位置单独保存，不覆盖独立模式的每屏续播记录。开启声音时，由主屏（无主屏时按确定的布局顺序选定的一屏）持有音频和共享续播记录；初始化先完成所有屏幕登记再加载，避免非主屏短暂输出声音，退出时也不由各屏随机覆盖共享位置。
- 当前 Windows 与 macOS 宿主提供跨屏接口。Windows standalone 测试窗口和当前 Linux 单输出宿主不提供跨屏能力；界面禁用并说明原因。保存的跨屏偏好若遇到不支持的宿主/拓扑，会暂时退回独立模式且明确提示，不把复制模式冒称跨屏。

## 静态图与暂停兜底

静态图片和导入时生成的视频首帧使用同一画布映射，按每屏当前模式的 backing 像素尺寸生成 PNG，再交给系统壁纸接口。Retina 屏的逻辑裁切区域与输出栅格尺寸分离，缓存键也包含输出像素尺寸；不把低分辨率逻辑点位图当作原生像素输出。fill/fit/stretch 在跨屏静态图中由图片映射实现；视频根据实际渲染器能力处理。静态图单屏的旧系统壁纸路径不因此宣称支持所有自定义适配方式。

裁切在每屏工作队列执行，不阻塞原生 UI。缓存键包含素材路径、文件大小/修改时间、画布/输出几何和适配方式。采用先裁切目标区域的缩放器，不分配完整虚拟桌面位图；图片解码跨屏串行，源图限制 64 MP、单屏输出限制 32 MP。原生画布每轴最多 32767 个桌面坐标单位；MF 的当前请求上限另外为 16384 像素/轴，GPU/平台实际限制仍可能更低，失败会报告，不宣称任意大画布可运行。

退役屏幕队列在耗时裁切前后检查关闭状态，避免拓扑切换后旧任务重新覆盖系统壁纸。原生窗口关闭检查对象所有权，避免重用的 HWND/NSWindow 标识被旧任务关闭。

## 必须补做的真机验收

1. Windows mpv/MF 与 macOS AVF 的真实双屏/三屏画面：负坐标、横竖屏混排、上下错位、不同 DPI/缩放与边界接缝。
2. 同样显示器数量下的重新排列、分辨率/缩放变化、更换显示器和主屏切换；拔插、睡眠恢复、Explorer/Space 恢复不产生孤立窗口或旧画面覆盖。
3. fill/fit/stretch 与静态首帧兜底的一致性；不支持的后端控制必须保持可见的能力边界。
4. 每屏全屏/遮挡和手动暂停后恢复；其他屏继续播放；不把分屏暂停产生的时间差误报为逐帧同步。
5. 实际 GPU 纹理/交换链限制、每屏独立解码的内存与功耗、跨 GPU 输出。当前实现未测得节电量，也没有单解码器的性能承诺。
